# Тесты

## Стек
- **Test runner по проекту**: Vitest (`npx vitest run`) или Jest (`npm test`/`jest`). Смотри `package.json` проекта, не навязывай свой
- Конфиг в корне (`vitest.config.ts` / `jest.config.*`)
- Тесты рядом с кодом: `*.spec.ts`, иногда в `test/`
- Фикстуры: `test/fixtures/` (сохранённые HTML/JSON ответы внешних API)

## Жёсткие правила
- При изменении покрытого тестом кода — обнови тест в том же коммите
- Bug fix без regression-теста — повод задержаться, баг вернётся
- Перед коммитом — прогон тестов локально, красный тест блокирует коммит
- Запрещено `it.skip(...)` / `.skip` без TODO+срока
- `--no-verify` при коммите запрещён

## CI как hard gate
- Если деплой гейтит рестарт на тестах (`deploy.sh` запускает `npm test -- --ci` между build и `pm2 restart` под `set -e`) — **красный тест на main блокирует весь будущий деплой**, прод остаётся на старой версии
- После push в main, где CI завязан на тестах, — проверяй, что pipeline зелёный
- Тест-гейт в деплое не обходить (`--no-verify`, скип шага) — чинить причину

## Когда добавлять
- Новый публичный метод сервиса с нетривиальной логикой → unit тест
- Новый endpoint → e2e/orchestration тест
- Новый парсер/маппер внешних API → snapshot тест на сохранённой фикстуре
- Любой fix баг-репорта → regression-тест

## Когда НЕ нужен
- Геттеры, рефакторинг, переименования
- Прямая обвязка DI токенов без логики
- Только комментарии/типы/форматирование

## Подходы
- **Парсеры внешних источников**: фикстура = сохранённый HTML/JSON в `test/fixtures/`. Тест проверяет:
  - количество распарсенных элементов
  - ключевые поля первого элемента (smoke)
  - инварианты на всех элементах (валидный URL, неотрицательная цена и т.д.)
  - граничные случаи (пустой ввод, отсутствующие поля)
- **DB-зависимые тесты**: testcontainers (реальный Postgres) или явный mock repository. Для file-SQLite-проектов — in-memory datasource (`:memory:`)
- **Внешние HTTP / SDK**: не делать live-запросов в тестах — мокать на границе (`undici.request`, SDK-клиент, спавн-обёртку)

## Mock-the-boundary
- Мокаем **только границы** (сеть, БД, внешние SDK, дочерние процессы), не внутренности
- Глубокие моки внутренней логики — запах, тест проверяет мок, а не код
- В тестах никаких реальных сетевых вызовов (YouTube, LLM API, scraper-таргеты)

## Запрещено
- `--no-verify` при коммите и обход тест-гейта в деплое
- Глубокие моки (мокаем только границы)
- Удалять «сломавшийся» тест без разбора причины
- Live HTTP-запросы в unit-тестах
